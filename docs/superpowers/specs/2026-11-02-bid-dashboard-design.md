# 회계법인 용역 공공입찰 대시보드 — 설계 문서

작성일: 2026-11-02
상태: 빌더 검토 반영 완료, 사용자 최종 승인 대기

## 1. 의도와 배경

사용자는 회계법인 소속으로 공공기관 업무를 담당한다. 매일 아침 나라장터(g2b.go.kr)에 접속해
공고명을 "회계/세무/재무/실사/평가" 등으로 검색하고 입찰 정보를 수작업으로 확인해 왔다.
이 조회를 자동화해, 매일 아침 갱신된 결과를 PC와 휴대폰에서 같은 URL로 확인하는 것이 목표다.

대상은 두 트랙이다.
- **공공기관**: 나라장터 용역 입찰공고 (국가·지자체·공공기관).
- **아파트**: K-apt(공동주택관리정보시스템) 전자입찰 공고 중 회계감사 등 회계 관련 용역.

사용자 조직은 전남광주 지역에 있다. 공고기관이 전남광주에 있거나, 지역제한 경쟁입찰에서
전남광주 또는 호남(광주·전남·전북)으로 제한된 공고는 다른 공고보다 눈에 띄게 보여야 한다.

## 2. 목표 / 비목표 / 실패 조건

### 목표
1. 매일 07:00(KST) 자동 수집·갱신. 사람 개입 없음.
2. 한 URL에서 4개 화면: 대시보드, 캘린더, 지역 지도, 낙찰 축적.
3. PC·모바일 동시 대응(반응형).
4. 공고는 공고번호 기준으로 누적 저장. 마감 후에도 이력이 남고, 개찰 후 낙찰 정보가 붙는다.
5. 관심지역(전남광주·호남) 공고를 강조 표시하고 따로 집계한다.
6. 키워드·제외어·관심지역을 설정파일에서 코드 수정 없이 바꿀 수 있다.

### 비목표 (이번 범위 밖)
- 푸시 알림, 이메일 발송.
- 투찰·낙찰 예측, 사정률 분석 같은 고급 분석.
- 나라장터 로그인이 필요한 기능(제안서 제출, 첨부파일 다운로드).
- 공사·물품 입찰. 용역만 다룬다.
- 시군구 단위 지도. 시도 단위까지만.

### 실패 조건 (동작해도 실패로 간주)
- 수집이 조용히 실패해 어제 데이터가 오늘 데이터처럼 보이는 것. 마지막 성공 시각과 실패 여부를 화면에 반드시 표시한다.
- 키워드 매칭 노이즈로 회계법인과 무관한 공고(예: 건축물 안전평가, 환경영향평가)가 다수 섞이는 것.
- 모바일에서 표가 잘려 핵심 정보(공고명·기관·마감일)를 못 읽는 것.
- 인증키가 저장소에 노출되는 것.

## 3. 제약

- 데이터 출처는 공공데이터포털(data.go.kr) OpenAPI 4종. 사용자는 인증키를 이미 보유하고 4개 서비스 모두 활용신청 승인 상태.
  개발계정 일일 트래픽: 나라장터 2종 각 1,000건/일, 공동주택 2종 각 5,000건/일. 하루 수집은 서비스별 100건 이내로 설계한다.
- 호스팅은 GitHub Pages(공개 저장소, GitHub 계정 wg5809-beep). 서버·DB 없음. 모든 상태는 저장소 안의 JSON 파일.
- 인증키는 GitHub Actions Secret `DATA_GO_KR_SERVICE_KEY`에만 둔다. 로컬 개발은 `.env`(gitignore).
- 정적 사이트이므로 브라우저에서 API를 직접 호출하지 않는다(인증키 노출 방지). 브라우저는 저장소의 JSON만 읽는다.
- 외부 유료 서비스·지도 API 키 사용 금지. 지도는 저장소에 포함한 SVG.
- 사용자 환경: Windows 11, Python 3.14, Node 26, gh CLI 로그인 완료.

국토교통부 공동주택 API는 파라미터 체계가 다르므로 빌더가 명세(data.go.kr 상세기능)로 확인한다.

## 5. 수집 규칙

### 5.1 공공기관(나라장터)
- 매일 "등록일시" 기준 최근 3일 범위를 조회한다(하루 누락 시 자동 보정). 키워드마다 `bidNtceNm` 검색 1회 + 페이지네이션.
- 키워드(포함, OR): 회계, 세무, 재무, 실사, 평가, 감사, 결산, 원가, 자산재평가, 타당성, 사업성.
- 제외어(공고명에 포함되면 제외): 안전평가, 안전점검, 환경영향평가, 교통영향평가, 성능평가, 내진성능, 정밀안전, 구조안전, 건축물 평가, 소방, 시설물.
  감정평가는 기본 포함(회계법인도 수행). 제외어는 config에서 수정 가능.
- 첫 실행(백필)은 최근 90일을 월 단위로 나눠 수집한다.
- 낙찰 추적: 보유 공고 중 개찰일이 지났고 낙찰 정보가 없는 건이 있으면, "개찰일시" 기준 최근 7일 범위로 용역 낙찰 목록을 조회해 공고번호+차수로 로컬 조인한다. 공고별 개별 호출은 하지 않는다(트래픽 절약).
  7일 범위에 안 잡히는 오래된 미낙찰 건은 백필(수동 실행, 60일 이상 범위)로 재조회한다(2026-11-11 변경: 일요일은 수집하지 않고 주 1회 일요일 재조회도 없앰). 60일 지나도 낙찰 정보가 없으면 "결과 미확인"으로 둔다.
- 유찰·재입찰은 개찰결과 오퍼레이션의 진행상태로 표시한다.
- 변경·취소 반영(작성자 판단): 등록일시 기준 목록 조회가 변경·취소 공고를 같은 공고번호의 차수 증가 + 공고종류(`ntceKindNm`)로 돌려주므로 별도 변경이력 호출 없이 이를 병합해 마감일·개찰일·공고명 변경과 취소를 덮어쓴다. 상태에 "취소"를 추가한다. 변경 전 값은 `history` 배열에 남긴다. (계획 수립 시 변경이력 오퍼레이션 대신 이 방식으로 확정.) 반영하지 않으면 캘린더가 연장 전 마감일을 계속 보여주므로 실패 조건에 해당한다.
- 참가제한지역 확보(작성자 판단): 목록 응답에 참가제한지역명이 없으면 `getBidPblancListInfoPrtcptPsblRgn`(참가가능지역)을 같은 날짜 범위로 일괄 조회해 공고번호로 로컬 조인한다. 그래도 비는 건은 지역제한여부(Y/N)만 표시한다. "공고별 개별 호출 금지"는 낙찰 추적에만 적용되는 원칙이며, 참가가능지역은 하루 호출 합계가 100건을 넘지 않는 범위에서 개별 보완 호출을 허용한다.

### 5.2 아파트(K-apt)
- 매일 "공고일" 기준 최근 3일 범위를 조회한 뒤 로컬에서 공고명 키워드 필터. 아파트 트랙 키워드: 회계감사, 외부회계감사, 회계, 세무, 결산, 장기수선충당금 검토.
  아파트 공고는 "청소·경비·승강기" 등 무관한 건이 대부분이므로 키워드 필터를 반드시 적용한다.
- 수집 지역은 **전국**(사용자 결정 변경, 2026-11-02 — 처음 호남만으로 정했으나 전국 진행중 회계공고가 2건뿐이라 넓힘). config `apt_regions`가 빈 목록이면 전국, 호남만 보려면 [전남광주, 전북]. API가 시도 필터를 지원하면 호출 시 적용하고, 아니면 공고명 접두어/시도 필드로 로컬 필터한다. 지역을 넓히려면 config만 바꾼다.
- 결과: 마감일이 지난 보유 공고에 대해 결과공지 서비스를 공고일 범위로 조회해 공고명+단지명으로 조인하고, 참여업체·선정업체·낙찰금액을 붙인다.

### 5.3 지역 판정 (공고마다 `region` 1개 + `interest` 플래그)
- 시도 단위. 2026년 기준 광주·전남은 "전남광주통합특별시"로 통합되었으므로 지도·집계에서 **전남광주** 1개로 취급. 구 명칭 "광주광역시"·"전라남도"도 전남광주로 정규화한다.
- 나라장터: ① 참가제한지역명(`prtcptLmtRgnNm`)이 있으면 그것, ② 없으면 공고기관명/수요기관명에서 시도명·광역시명·주요 시군명 사전으로 추출, ③ 둘 다 없으면 "전국/미분류".
- K-apt: 공고명 앞의 `[경기]`, `[전남광주]` 같은 지역 접두어(K-apt 사이트 표기)를 1차로 쓰고, 응답에 시도 코드/주소 필드가 있으면 그것을 우선한다. 둘 다 없으면 미분류. 단지 기본정보 API 같은 추가 서비스는 쓰지 않는다.
- 기관 소재지 판정은 이름 사전으로는 부족하다. 빛가람혁신도시 이전기관(한국전력공사, 한전KDN 등)은 이름에 지역이 없다. 그래서 config에 **전남광주 소재 기관 목록**(`interest_institutions`, 기관명 부분일치)을 두고 소재지 판정에 함께 쓴다. 초기 목록(작성자 제안, 사용자 확인 필요): 한국전력공사, 한전KDN, 한국전력거래소, 한국농어촌공사, 한국농수산식품유통공사, 한국콘텐츠진흥원, 사립학교교직원연금공단, 우정사업정보센터, 국립전파연구원, 한국인터넷진흥원, 한국문화예술위원회, 한국방송통신전파진흥원, 농림식품기술기획평가원, 한국농촌경제연구원, 광주과학기술원, 한국광기술원, 광주테크노파크, 전남테크노파크, 전남대학교, 조선대학교, 광주은행, 한국에너지공과대학교, 광주도시공사, 전남개발공사, 광주광역시도시철도공사.
- `interest`(관심지역) 판정은 두 목록으로 나눈다(사용자의 말 그대로: "기관이 전남광주에 있거나, 지역제한이 전남광주 또는 호남").
  ① 소재지 목록 `interest_home_regions` 기본 [전남광주] + `interest_institutions` 기관명 목록 → 공고기관 또는 수요기관이 해당하면 true, 근거 "본사 소재".
  ② 지역제한 목록 `interest_limit_regions` 기본 [전남광주, 광주, 전남, 전북, 호남] → 참가제한지역에 포함되면 true, 근거 "지역제한".
  전북 소재 기관의 전국 공고는 ①에 해당하지 않으므로 강조하지 않는다. 두 목록 모두 config에서 수정 가능.
  판정 근거를 함께 저장해 화면에서 "본사 소재" / "지역제한"으로 구분 표시한다.

### 5.4 저장 모델 (저장소 `data/` 폴더, JSON)
- `data/awards.json`에는 공고명·기관·지역 등 핵심 공고 필드를 복제해 두어, 공고가 보존기간 만료로 정리된 뒤에도 낙찰 행이 혼자 읽힌다(작성자 판단).
- `data/notices.json`: 공고 전체. 키 = `track + bidNtceNo + bidNtceOrd`(아파트는 공고번호 또는 단지코드+공고일+공고명 해시). 필드: 트랙, 공고번호, 차수, 공고명, 공고기관, 수요기관, 공고일시, 입찰마감일시, 개찰일시, 기초금액/추정가격, 계약방법, 낙찰방법, 지역제한여부, 참가제한지역, region, interest, interest_reason, 원문 URL(나라장터 `bidNtceDtlUrl`, K-apt 상세), 상태(공고중/마감/개찰완료/낙찰/유찰/재입찰/결과미확인), 최초수집일, 최종갱신일, 재공고 여부.
- `data/awards.json`: 낙찰 정보. 공고 키로 연결. 낙찰자명, 사업자번호, 대표자, 낙찰금액, 예정가격, 낙찰률, 참가업체수, 개찰일시, 최종낙찰일. 영구 보존(삭제하지 않음).
- `data/meta.json`: 마지막 실행 시각, 성공/실패, 서비스별 호출 횟수, 신규 건수, 오류 메시지.
- 보존: 공고는 공고일 기준 2년 지난 건을 정리(config). 낙찰은 영구.
- 모든 쓰기는 기존 파일을 읽어 새 객체를 만들어 통째로 교체(불변 패턴). 임시파일 → rename.

## 6. 화면 설계

단일 정적 사이트. 상단 탭 4개. 모든 화면 공통: 트랙 토글(전체/공공기관/아파트), 관심지역만 보기 토글, 검색창(공고명·기관), 마지막 갱신 시각과 수집 상태 배지(성공=녹색, 실패=빨강 + 오류 요약).
관심지역 공고는 모든 화면에서 같은 강조색(예: 주황 테두리 + "전남광주" 또는 "호남 제한" 배지)으로 표시한다.

### 6.1 대시보드
- 상단 KPI 4개: 오늘 신규, 7일 내 마감, 관심지역 진행중, 이번 주 개찰 예정.

- 낙찰·유찰·재입찰·결과미확인 상태인 공고 전체. 기본 정렬 개찰일 내림차순.

## 12. 추가 변경 (2026-11-02 오후, 사용자 요청)

### 12.1 업무 분류: 주타겟 / 기타
- 사용자 회계법인 역량 9개를 **주타겟 업무**로 두고, 공고명으로 분류한다: 회계감사, 세무조정, 세무조사대응, 세무진단, 세무컨설팅, 기업실사, 공정가치평가, 사업비정산, PA. 어디에도 안 맞으면 **기타**.
- 설정 `service_lines`(순서 = 우선순위, 각 항목 name/keywords/exclude). 분류는 순수 함수이며 매 수집 때 저장된 전체 공고를 다시 분류하므로 설정 변경이 과거 공고에도 반영된다.
- 저장 모델 `Notice.category`("target"/"other"), `Notice.service`(업무명 또는 null). 구버전 JSON은 기본값 other로 읽힌다.
- 수집 키워드에 정산·공정가치·세무조정·세무조사 추가, 제외어에 정산시스템·요금정산 추가.
- 화면: 공통 필터에 "전체 업무/주타겟/기타" 세그먼트, 공고 행마다 업무 칩(주타겟은 파란 그라데이션, 기타는 회색), 대시보드는 관심지역 → 주타겟 진행중 → 기타 진행중(접힘) 순, KPI에 "주타겟 진행중" 추가, 낙찰 CSV에 구분·업무 열 추가, 상세 모달에 업무 구분 행 추가.
- 작성자 판단: "PA"는 공공부문 회계자문(회계처리·결산지원·복식부기·원가계산 등)으로 해석했다. 기술가치평가·기후가치평가는 공정가치평가에서 제외, 감정평가는 기타로 둔다. 세무조사 관련 교육·연구 공고는 제외.

### 12.2 디자인 전면 수정
- 참고 자료(사용자 제공 제안서 PDF)의 톤을 따른다: 연한 하늘색 그라데이션 배경, 흰색 라운드 카드(반경 18px)와 부드러운 그림자, 파란 그라데이션 강조(#7fd4ff→#4a9af5), 파란 표 머리글(흰 글씨) + 줄무늬 행, 섹션 제목 앞 작은 파란 사각 불릿, 큰 숫자 KPI("23건" 식 단위 표기), 알약형 탭·필터, Pretendard 글꼴(CDN, 실패 시 시스템 글꼴).
- 관심지역 강조(주황)는 기능상 유지한다. 모바일(≤768px)은 표를 카드로 바꾸는 기존 규칙을 유지한다.

## 13. 추가 변경 (2026-11-06, 사용자 요청): 발주계획

사용자가 발주계획 API 활용신청을 마치고 "프로젝트에서 확인할 수 있게" 요청했다. 질문 없이 진행하라는 지시에 따라 아래는 모두 작성자 판단이다.

### 13.1 데이터 소스 (실호출 확인)
- 조달청_나라장터 발주계획현황서비스 `apis.data.go.kr/1230000/ao/OrderPlanSttusService`, 오퍼레이션 `getOrderPlanSttusListServcPPSSrch`(용역). 기존 인증키로 호출된다.
- 발주년월(`orderBgnYm`~`orderEndYm`)과 게시일시(`inqryBgnDt`~`inqryEndDt`)를 **함께** 줘야 조건이 적용된다. 하나라도 빠지면 조건이 무시되고 최근 게시분만 내려온다. 게시일시는 1개월 제한이 없다(22개월 조회 성공).
- `bizNm`은 사업명 부분일치. `bidNtceNoList`는 "공고번호 13자리 + 차수 3자리"를 쉼표로 이은 값이고, 비어 있으면 아직 공고 전이다.
- 용역만 수집한다(물품·공사·외자는 회계법인 업무와 무관).

### 13.2 수집 규칙
- 범위: 발주 예정월이 `plan_past_months`(3)개월 전 ~ 내년 12월, 게시일이 `plan_posted_lookback_days`(730)일 이내.
- 키워드: `public_keywords`별로 1회씩 조회(하루 24회 안팎)하고 사업명에 `public_keywords`/`public_exclude`를 그대로 적용한다. 업무 분류(`service_lines`)·관심지역 판정도 공고와 같은 규칙이다. 지역은 발주기관명 → 총괄기관명에서 뽑는다(계획에는 참가제한지역 정보가 없다).
- 저장: `data/plans.json`. 키 = `plan:` + 발주계획통합번호. 필드: 사업명, 발주기관, 총괄기관, 기관유형, 발주 예정월, 예정금액, 계약방법, 조달방식, 담당부서, 전화, 게시일시, 변경일시, 연결 공고번호, region, interest, 업무 분류, 원문 URL, 최초수집일.
- 매 수집 때 전체를 다시 받는다. 모든 키워드 호출이 성공하면 받은 목록으로 통째 교체(원본에서 삭제된 계획은 사라짐), 하나라도 실패하면 기존 계획을 남기고 받은 것만 갱신한다. 범위를 벗어난 예정월은 정리한다.
- 담당자 실명(`ofclNm`)은 저장하지 않는다. 공개 저장소이므로 부서명·대표전화까지만 두고, 실명은 나라장터 원문 링크에서 확인한다.
- `meta.json`에 `plan_count`, `new_plans` 추가. 발주계획 호출 실패도 다른 소스와 같이 수집 실패 배지로 드러난다.

### 13.3 화면
- 탭 "발주계획" 추가(5번째). 공통 필터 중 업무 구분·관심지역만·검색이 적용되고, 트랙이 "아파트"면 안내 문구만 보인다.
- 탭 전용 필터: 상태(공고 전 전체 기본 / 발주 예정만 / 예정월 경과만 / 공고됨 / 전체), 발주월, 지역, 계약방법, CSV 다운로드.
- 상태: 공고 전 / 예정월 경과(예정월이 지났는데 연결 공고 없음) / 공고됨. 최근 7일 안에 게시·변경된 계획에는 "신규" 칩.
- 정렬: 다가오는 달(이번 달 포함, 가까운 달부터) → 예정월 미정 → 지난 달(최근 달부터). 같은 달은 금액 큰 순.
- 구역(2026-11-06 사용자 요청): 예정월이 지난 계획을 따로 분류한다. 상태별로 "발주 예정" → "예정월 경과 · 공고 없음" → "공고된 계획" 구역을 나눠 표시하고, 구역 제목에 건수와 예정금액 합계를 붙인다. 해당 건이 없는 구역은 숨긴다.
- 요약: 발주 예정 수, 예정월 경과 수, 주타겟, 관심지역, 최근 7일 게시·변경.
- 행을 누르면 상세 모달. 연결된 입찰공고가 대시보드에 있으면 그 공고 상세로 넘어가고, 없으면 공고번호만 보여준다.
- 대시보드·캘린더·지도 화면은 바꾸지 않았다(발주계획은 날짜가 "월" 단위라 캘린더·마감 임박 목록에 섞지 않음).
